# UI 与业务逻辑进一步优化

## Goal

基于现有 DianMao Android Compose 应用，对当前主流程进行一次有边界的 UI 与交互逻辑优化，让用户更快捕获事项、更容易理解当前工作状态，并降低搜索、浏览、编辑、完成和返回导航中的认知负担。优化应保持现有四象限、时间提醒、日历、归档、备份和完成复盘能力，不引入新的产品大方向。

## What I Already Know

* 项目是单模块 Android 应用，主要 Compose UI 与页面状态集中在 `app/src/main/java/fun/han1997/dianmao/MainActivity.kt`。
* 当前主页包含应用头部、搜索、统计摘要、时间关注区和四象限看板；四象限详情支持拖拽排序。
* 当前逻辑包含任务新增/编辑、完成备注、重复任务、提醒调度、系统日历、归档、备份恢复和应用内返回目标解析。
* 产品原则是“捕获在前，分类在后”，强调快速、清晰、原生熟悉和完成后的记忆沉淀。
* 设计系统定义了暖 terracotta 主色、日历蓝语义色、低对比表面层级、紧凑可读的系统字体和仅用于状态变化的动效。
* 当前工作区已有用户未提交的 `.impeccable/` 与 `.opencode/` 文件，本任务不应修改或纳入任务提交，除非明确需要。

## Assumptions (Temporary)

* 本轮优先解决现有主流程中最明显的可用性、状态一致性和视觉层级问题，而不是全面重写界面。
* 优化应优先复用现有数据模型和 repository 能力，避免无明确需求的数据库迁移。
* 需要以代码审查和现有测试为基础识别问题，不凭空增加功能。

## Requirements (Evolving)

* 先完成现有 UI 与逻辑的审查，列出可验证的问题和建议改动。
* 本轮以 UI 与信息层级为主，优先优化主页、四象限看板、任务行、任务详情和新增/编辑表单。
* 任务行保持当前结构，不改为常驻多按钮操作栏；通过更清晰的完成入口、菜单 affordance、触摸反馈、语义标签和状态展示增强可发现性。
* 优先改善高频主流程的可读性、操作可发现性、选中/完成/保存等状态反馈，以及窄屏和系统字体放大时的布局稳定性。
* 同时处理空状态、搜索无结果、长标题/长文本、系统字体放大、叠加页面返回和保存/异步失败反馈等关键稳健性问题。
* 保持现有业务能力和数据模型，不把备份、归档面板作为本轮主要视觉改造目标，除非审查发现明显阻塞问题。
* 所有改动应遵守 `DESIGN.md` 与 Compose 规范，保持无障碍触达尺寸、文字缩放和返回行为。
* 逻辑改动必须覆盖空状态、筛选无结果、重复任务、权限未授予、异步失败和叠加页面返回等边界。
* UI 改动应保持移动端可用，并避免增加装饰性复杂度。

## Acceptance Criteria (Evolving)

* [ ] 用户确认本轮优先级和页面范围。
* [ ] 主页、四象限、任务行、详情和任务表单形成一致的信息层级与操作反馈。
* [ ] 长标题、长文本、空状态、无结果状态和系统字体放大不会造成关键操作不可用。
* [ ] 叠加页面按正确优先级响应返回，保存和异步失败有清晰且不丢失的反馈。
* [ ] 主页及纳入范围内的页面层级、操作反馈和状态展示更清晰。
* [ ] 任务浏览、编辑、完成、返回和异步操作行为无回归。
* [ ] 相关单元测试通过，lint、assemble 和 `git diff --check` 通过。
* [ ] 新增的持久化规则或通用交互约束被记录到对应 spec（如确有必要）。

## Definition of Done

* 需求范围已确认并记录。
* 完成最小必要代码改动和相关测试。
* 通过项目质量检查。
* 任务代码变更按流程提交，未纳入无关工作区文件。

## Technical Approach

先审查现有 Compose 主流程并以最小改动修复可验证的视觉与交互问题。优先复用既有组件、颜色、形状和 repository 接口；UI 状态保持单向传递，异步操作增加明确的进行中、成功和失败反馈。对可独立验证的筛选、时间归类和返回目标逻辑补充单元测试，并通过 Android lint、单元测试与 debug assemble 验证。

## Decision (ADR-lite)

**Context**: 当前核心能力已经完整，但主界面与任务流程仍可在信息层级、操作可发现性和边界状态方面进一步打磨。

**Decision**: 采用 UI 优先的渐进优化方案，覆盖主页、四象限、任务行、详情和表单；保留任务行现有结构，通过视觉语义、反馈和无障碍增强提升可发现性，同时修复直接影响这些界面的关键状态问题。

**Consequences**: 能在不改变数据模型和产品架构的前提下提升日常体验；本轮不追求所有辅助面板统一重做，也不引入新的导航框架或组件库。

## Out of Scope

* 不改变四象限产品模型。
* 不新增账号、云同步、多人协作或全新导航架构。
* 不在没有明确收益的情况下引入第三方 UI 库或数据库迁移。
* 不修改用户已有的 `.impeccable/`、`.opencode/` 工作区变更。
