# 修复编辑事项返回行为

## Goal

修复“编辑事项”界面的返回行为：从二级页面进入编辑事项后，返回应先关闭编辑事项界面并回到二级页面，而不是绕过二级页面直接回到主页面。由于该问题已多次修复未生效，本任务还要定位根因并记录防复发约束。

## What I Already Know

* 用户反馈：“编辑事项，返回不会关闭编辑事项而是二级页面返回主页面”，并且“改了好几次没修复”。
* 产品是个人 Android 任务管理应用，返回行为应符合原生 Android 预期，避免非标准控件和令人困惑的导航。
* 近期提交/任务历史包含编辑返回和 predictive back 相关修复，需要检查旧方案为什么未覆盖本场景。
* 旧方案添加了多个 `BackHandler`，并假设源码顺序等于返回消费顺序。
* 当前 `activity-compose` 已是 `1.9.3`，问题不再是预测返回支持版本不足。

## Assumptions

* “编辑事项”指已有事项的编辑界面，不是新建事项。
* “二级页面”指从主页面进入的详情、清单、日历、完成记录或类似子页面。
* 系统返回手势、系统返回键和应用栏返回按钮都应保持一致。

## Requirements

* 从任意二级页面打开编辑事项后，返回先关闭编辑事项并恢复二级页面。
* 编辑事项关闭后，二级页面的导航状态不得被同步弹回主页面。
* 应覆盖应用栏返回和 Android 系统返回/预测返回路径。
* 修复应定位并处理导航栈根因，而不是只给某个按钮加局部跳转。
* 返回逻辑必须使用显式优先级，不能依赖多个 Compose `BackHandler` 的注册顺序。

## Acceptance Criteria

* [ ] 从二级页面进入编辑事项，点击编辑页返回按钮后回到该二级页面。
* [ ] 从二级页面进入编辑事项，使用系统返回/手势后回到该二级页面。
* [ ] 从主页面进入编辑事项，返回行为仍然合理，不出现空白页或重复页面。
* [ ] 不破坏新增事项、事项详情、主页面导航等既有路径。
* [ ] 至少通过静态分析或相关测试验证。

## Definition of Done

* 代码修复完成。
* 执行可用的 lint/analyze/test/build 检查。
* 记录为什么之前容易修错，以及以后如何避免同类问题。

## Out of Scope

* 重做编辑事项 UI。
* 改动任务数据模型或后端存储。
* 新增大范围导航架构，除非现有代码显示这是必要根因。

## Technical Notes

* 相关文件：`app/src/main/java/fun/han1997/dianmao/MainActivity.kt`。
* 当前实现没有使用 Navigation Component，主页面、二级象限详情、编辑面板都由 Compose state 控制。
* 根因：`activePriority` 的二级页 `BackHandler` 是条件注册；进入二级页后它比一直存在但当时 disabled 的新增/编辑面板 `BackHandler` 更晚注册，因此两者同时 enabled 时可能由二级页 handler 先消费返回。
* 修复方向：使用单个顶层 `BackHandler`，按显式顺序关闭最顶层状态：备份面板、编辑/新增面板、二级页。
